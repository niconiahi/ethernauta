# EIP-6963 — wallet discovery + persistence

Wallets dispatch `eip6963:announceProvider`; dapps dispatch
`eip6963:requestProvider` to nudge late ones. Each announce
carries `{ info: { name, rdns, uuid, icon }, provider }`.

The Provider object cannot be serialized — only the `rdns`
identifier can. Persistence is *re-discovery keyed by the
persisted identifier*: store rdns on pick, re-issue the
announce request on the next page load, match the
announcement, recover the live detail.

- **`set_provider_detail({ store, key, provider_detail })`** —
  persists the user's choice (writes only `detail.info.rdns`).
- **`get_provider_detail({ store, key, target?, ms? })`** —
  re-runs the 6963 handshake, filters by rdns, returns
  `EIP6963ProviderDetail | null` (null if the wallet
  uninstalled).
- **`clear_provider_detail({ store, key })`** — clears
  the persisted selection.

The `Store` shape is `{ get, set, remove }` — synchronous
get/set/remove returning `string | null`. `window.localStorage`
fits via the `web_storage` adapter; in a Chrome MV3 background
a `chrome.storage.local`-backed wrapper works too; in tests, an
in-memory `Map`-backed shim works.
