# ERC-7683 — cross-chain intents

Sign a `GaslessCrossChainOrder` on Sepolia and ship the
signed payload to a 7683 settler / relayer. The user only
ever signs an EIP-712 message — fillers are responsible for
opening the order on-chain via `openFor()` and filling on
the destination.

## What's happening

1. The dapp assembles a `GaslessCrossChainOrder` —
   originSettler, user, nonce, originChainId,
   openDeadline, fillDeadline, orderDataType, orderData.
2. The dapp computes the EIP-712 hash under the settler's
   domain (`hash_gasless_order`) — most reference settlers
   use this hash as the on-chain `orderId`.
3. The dapp asks the wallet to sign that typed data via
   `eth_signTypedData_v4`. The wallet pops a typed-data
   confirmation and returns a 65-byte signature.
4. A filler picks up `(order, signature, originFillerData)`
   and calls `openFor` on the origin settler. The dapp
   surfaces the payload here — pipe it into your relayer
   of choice (Across testnet, in-house solver, …).
5. The destination settler runs `fill(orderId, originData,
   fillerData)` to release funds to the recipient.

## The code

```ts
import { eip155_11155111 } from "@ethernauta/chain"
import {
  build_gasless_order,
  hash_gasless_order,
  sign_gasless_order,
} from "@ethernauta/erc/7683"
import {
  create_signer,
  encode_chain_id,
  http,
} from "@ethernauta/transport"

const SEPOLIA_CHAIN_ID = encode_chain_id({
  namespace: "eip155",
  reference: eip155_11155111.chainId,
})

const SEPOLIA_REF_HEX = "0xaa36a7" as const
const OP_SEPOLIA_REF_HEX = "0xaa37dc" as const
const USDC_SEPOLIA = "0x1c7D4B196Cb0C7B01d743Fbc6116a902379C7238"
const USDC_OP_SEPOLIA = "0x5fd84259d66Cd46123540766Be93DFE6D43130D7"

// Settlers tag their order-data shape with a 32-byte magic
// so they can multiplex layouts. Replace with the type your
// settler expects (often keccak("YOUR_ORDER_TYPE")).
const ORDER_DATA_TYPE = `0x${"00".repeat(32)}` as const

const signer = create_signer([
  {
    chainId: SEPOLIA_CHAIN_ID,
    transports: [
      http("https://ethereum-sepolia-rpc.publicnode.com"),
    ],
  },
])

// 1. Build the gasless order envelope. `window` controls
//    openDeadline (how long fillers have to open it on the
//    origin chain) and fillDeadline (how long they then
//    have to fill on the destination).
const order = build_gasless_order({
  originSettler: SETTLER,
  user,
  originChainId: SEPOLIA_REF_HEX,
  orderDataType: ORDER_DATA_TYPE,
  orderData:
    `0x${USDC_SEPOLIA.slice(2).padStart(64, "0")}${USDC_OP_SEPOLIA.slice(2).padStart(64, "0")}${OP_SEPOLIA_REF_HEX.slice(2).padStart(64, "0")}`,
  window: { open_window_s: 300, fill_window_s: 1800 },
})

const domain = {
  name: "ERC-7683 settler",
  version: "1",
  chainId: 11155111n,
  verifyingContract: SETTLER,
}

// 2. The settler's canonical orderId IS the EIP-712 hash.
const order_id = hash_gasless_order({ order, domain })

// 3. Ask the wallet to sign. The relayer picks up
//    (order, signature) and calls openFor() on the settler.
const signature = await sign_gasless_order({
  order,
  domain,
})(signer({ chain_id: SEPOLIA_CHAIN_ID }))
```

## What's intentionally left out

- **`orderData` schema.** The 7683 envelope is settler-agnostic.
  Each settler defines its own `orderData` layout, keyed by
  the `orderDataType` bytes32 magic. Plug in your settler's
  encoder before submitting.
- **Status polling.** The standard exposes `resolve` /
  `resolveFor` for simulation but doesn't define a status
  RPC — fillers typically expose their own API. The package
  ships the EIP-712 + struct bindings; the status surface is
  best built per-settler.
