# EIP-3668 — Secure offchain data retrieval

> [eips.ethereum.org/EIPS/eip-3668](https://eips.ethereum.org/EIPS/eip-3668)

A contract can defer reads to an off-chain backend by reverting with a custom error that names the gateway URLs to consult, plus a callback selector. CCIP-Read-aware clients recognise the revert, fetch the off-chain payload, then re-call the contract with the response folded in.

```ts
import { parse } from "valibot";
import { AddressSchema, BytesSchema } from "@ethernauta/core";
import { eth_call_ccip } from "@ethernauta/eip/3668";
import { create_reader, encode_chain_id, http } from "@ethernauta/transport";
import { eip155_1 } from "@ethernauta/chain/eip155-1";

const CHAIN_ID = encode_chain_id({ namespace: "eip155", reference: eip155_1.chainId });
const reader = create_reader([
  { chainId: CHAIN_ID, transports: [http("https://ethereum-rpc.publicnode.com")] },
]);

const to = parse(AddressSchema, "0xC1735677a60884ABbCF72295E88d47764BeDa282");
const input = parse(BytesSchema, "0x…");

// The wrapper runs the full protocol — initial eth_call, OffchainLookup
// detection, gateway fetch, callback eth_call — with recursive follow-ups
// up to max_redirects (default 4).
const result = await eth_call_ccip({ to, input })(
  reader({ chain_id: CHAIN_ID }),
);
void result;
```

## The protocol

A CCIP-Read-aware contract reverts with

```solidity
error OffchainLookup(
  address sender,
  string[] urls,
  bytes callData,
  bytes4 callbackFunction,
  bytes extraData
);
```

(selector `0x556f1830`). The client iterates `urls`, substitutes `{sender}` (lowercased) and `{data}` (the original `callData`), and either GETs (when the template contains `{data}`) or POSTs `{ data, sender }`. 4xx aborts the whole call; 5xx falls through to the next URL. On 2xx, the client builds callback calldata as `callbackFunction ‖ abi.encode(response, extraData)` and re-issues the `eth_call`. If that one also reverts with `OffchainLookup`, recurse up to `max_redirects` (the spec says implementations should support at least 4).

## Surface

| Export | Type | Purpose |
|---|---|---|
| `eth_call_ccip` | `Readable<Bytes>` | Wraps `eth_call` with automatic CCIP-Read resolution. The happy path most consumers want. |
| `parse_offchain_lookup_revert` | `(Bytes) => OffchainLookupError \| null` | ABI-decode a revert payload into the named fields. Returns `null` when the selector doesn't match. |
| `substitute_url` | `(string, Address, Bytes) => string` | Fill `{sender}` (lowercased per spec) and `{data}` placeholders in a single URL template. |
| `fetch_ccip` | `(args, fetch?) => Promise<Bytes>` | Iterate the URL list — GET / POST per `{data}` presence, 4xx aborts, 5xx falls through. Optional `fetch` for non-browser runtimes. |
| `build_callback_calldata` | `(Bytes4, Bytes, Bytes) => Bytes` | Prepend the callback selector to `abi.encode(response, extraData)`. |
| `OffchainLookupError` | type | Decoded shape: `{ sender, urls, callData, callbackFunction, extraData }`. |
| `CcipResponse` | type | Wire shape of the gateway response payload. |
| `CcipLookupError` | error class | Typed failure surface — `max-redirects`, `gateway-failed`, etc. |

## Why both the wrapper and the primitives

`eth_call_ccip` is the happy path. The primitives exist so consumers that need transparency (auditability, intermediate caching, custom retry policy) can compose their own loop. Both ship by design — the EIP-3668 folder owns the protocol; `@ethernauta/ens` consumes the wrapper for every resolver call.

## Composing with ENS

ENSIP-10 wildcard resolution requires CCIP-Read. Basenames (`*.base.eth`), Optimism names, Linea names, and any wildcard resolver route their `resolve(name, data)` through `eth_call_ccip` internally — the dapp calls `get_ens_address({ name: "jesse.base.eth" })` and CCIP-Read just works.

```ts
import { get_ens_address } from "@ethernauta/ens";
import { create_reader, encode_chain_id, http } from "@ethernauta/transport";
import { eip155_1 } from "@ethernauta/chain/eip155-1";

const CHAIN_ID = encode_chain_id({ namespace: "eip155", reference: eip155_1.chainId });
const reader = create_reader([
  { chainId: CHAIN_ID, transports: [http("https://ethereum-rpc.publicnode.com")] },
]);

// Resolves through the Base resolver on mainnet — CCIP-Read invisible to the call site.
const address = await get_ens_address({ name: "jesse.base.eth" })(
  reader({ chain_id: CHAIN_ID }),
);
void address;
```

## A note on scope

CCIP-Read does not introduce hosted infrastructure. The gateway URLs are chosen by the **contract author** — the library follows the redirects but never operates a gateway. That keeps M4 (no paid services) intact.
