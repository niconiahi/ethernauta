# Predeploys

> 🚧 **In progress — landing with slice 3 of the OP package plan.** Only `GasPriceOracle` ships in the current `@ethernauta/op` release; the rest of the table below is provisional and lists target addresses + spec references for the upcoming work.

OP Stack chains ship with a fixed set of system contracts at well-known `0x420…` addresses. Same code, same addresses, every OP Stack chain — Optimism, Base, Mode, Zora, Worldchain, Soneium, Lisk. This is what makes OP-Stack-wide tooling possible: bind the address once, the binding works on every chain in the family.

Authoritative reference: [Predeploys — OP Stack specs](https://specs.optimism.io/protocol/predeploys.html). Source: [`packages/contracts-bedrock/src/L2/`](https://github.com/ethereum-optimism/optimism/tree/develop/packages/contracts-bedrock/src/L2).

## Address registry

| Predeploy | Address | Purpose | Status |
|---|---|---|---|
| [`GasPriceOracle`](https://specs.optimism.io/protocol/predeploys.html#gaspriceoracle) | `0x420…000F` | L1 fee math (`getL1Fee`, `baseFee`, `decimals`, `gasPrice`, scalars). Used by [`estimate_op_fees`](/op/gas) and [`estimate_l1_fee`](/op/gas). | ✅ Shipped — 23 methods, autogenerated from `GasPriceOracle.abi.json` |
| [`L1Block`](https://specs.optimism.io/protocol/predeploys.html#l1block) | `0x420…0015` | Current L1 block context (`basefee`, `blobBaseFee`, `hash`, `number`, `timestamp`, `sequenceNumber`, batcher hash, blob-base-fee scalar). Populated by the sequencer every L2 block. | 🚧 Slice 3 |
| [`L2StandardBridge`](https://specs.optimism.io/protocol/predeploys.html#l2standardbridge) | `0x420…0010` | L2 side of the canonical bridge — withdrawals + deposit finalization. **Predeploy reads only — bridge methods land with the bridge phase.** | 🚧 Slice 3 |
| [`L2CrossDomainMessenger`](https://specs.optimism.io/protocol/predeploys.html#l2crossdomainmessenger) | `0x420…0007` | Generic L1 ↔ L2 message passing primitive. Same predeploy-read scope as L2StandardBridge. | 🚧 Slice 3 |
| [`L1FeeVault`](https://specs.optimism.io/protocol/predeploys.html#l1feevault) | `0x420…001A` | Collects the L1 data fee surcharge. | 🚧 Slice 3 |
| [`SequencerFeeVault`](https://specs.optimism.io/protocol/predeploys.html#sequencerfeevault) | `0x420…0011` | Collects the L2 priority fee. | 🚧 Slice 3 |

Additional predeploys defined by the spec but not currently planned for binding (out of scope until a consumer surfaces):

- `LegacyMessagePasser` (`0x420…0000`) — pre-Bedrock relic, kept for archival reads.
- `DeployerWhitelist` (`0x420…0002`) — disabled post-Bedrock.
- `L2ToL1MessagePasser` (`0x420…0016`) — withdrawal initiation. Lands with the bridge phase.
- `OptimismMintableERC20Factory` (`0x420…0012`) — factory for canonical-bridged ERC-20s.
- `ProxyAdmin` (`0x420…0018`) — owns upgrade rights on the rest of the predeploys.
- `BaseFeeVault` (`0x420…0019`) — collects the L2 base fee.
- `SchemaRegistry` / `EAS` (`0x420…20…21`) — Ethereum Attestation Service. Out of scope here; see [EAS docs](https://docs.attest.org/).

Full canonical list: [predeploys.go in op-bindings](https://github.com/ethereum-optimism/optimism/blob/develop/op-bindings/predeploys/predeploys.go).

## How predeploy methods are bound

Same pattern as the ERC bindings — autogenerated from the canonical ABI, output one curried method per ABI entry. `GasPriceOracle` ships 23 methods (matching the ABI's 23 entries). Bound paths:

```ts
import { contract } from "@ethernauta/transport"
import { GAS_PRICE_ORACLE_ADDRESS, getL1Fee } from "@ethernauta/op"
// (slice 3 will also export L1Block, L2StandardBridge, … from the same root)

const callable = getL1Fee([unsigned_tx_bytes])(
  contract({ chain_id: CHAIN_ID, to: GAS_PRICE_ORACLE_ADDRESS }),
)
// → Callable<Uint256>
```

The `to` address is a constant — the predeploy lives at the same address on every OP Stack chain — so the binding is chain-agnostic. Same call site works on Base, Mode, Zora, Optimism, all of them.

## Vendoring + codegen

Predeploy ABIs are vendored at a pinned commit SHA of `ethereum-optimism/optimism` and regenerated via `pnpm --filter @ethernauta/op generate` (lands with slice 3). The vendor strategy mirrors [`@ethernauta/erc` codegen](/tooling/erc-codegen) — pin to a specific commit, bump deliberately, document the bump cadence in the package README. Never track `develop`.
