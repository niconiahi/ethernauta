# @ethernauta/arbitrum

Arbitrum-specific primitives. Nitro precompile bindings, the `arb_*` consensus-side RPC namespace, the L1+L2 gas split, per-chain L1 deployment registry, Timeboost — everything that's true of every Nitro-stack chain (Arbitrum One, Nova, Sepolia, plus curated Orbit chains: Xai, ApeChain, Sanko, Proof of Play Apex, RARI, Treasure, Reya, Plume) but isn't part of L1 Ethereum.

```bash
pnpm add @ethernauta/arbitrum
```

The Yellow Paper substrate — accounts, EVM, RLP, EIP-1559, the `eth_*` method surface — lives in [`@ethernauta/eth`](/eth/overview). This package is the layer on top: the things [the Nitro stack](https://docs.arbitrum.io/) defines that Yellow Paper doesn't.

## What's in the Arbitrum layer

Nitro chains are EVM-equivalent at the execution layer, with a different block-production and fee model:

- **Block production.** A single sequencer orders L2 transactions and posts compressed batches to an [`Inbox`](https://docs.arbitrum.io/how-arbitrum-works/inside-arbitrum-nitro/#the-sequencerinbox-contract) on L1. A separate Rollup contract anchors L2 state to L1 via interactive (BoLD) or single-step fraud proofs.
- **Two-dimensional fee model.** Users pay L2 EIP-1559 execution gas *plus* an L1 batch-posting surcharge. Unlike OP Stack, Arbitrum hands back all four numbers (`gasEstimate`, `gasEstimateForL1`, `baseFee`, `l1BaseFeeEstimate`) in one call to the [`NodeInterface`](https://docs.arbitrum.io/build-decentralized-apps/precompiles/reference#nodeinterface) virtual precompile at `0x00…C8`. See [`/arbitrum/gas`](/arbitrum/gas).
- **Precompiles.** 16 Arbitrum-specific precompiles at `0x0064`–`0x00C8` — `ArbSys`, `ArbGasInfo`, `ArbRetryableTx`, `ArbAddressTable`, etc. Plus the `NodeInterface` virtual contract (bytecode is `0xfe`; the node intercepts calls). Bindings ship in slice 4.
- **Per-chain L1 deploys.** Bridge / inbox / outbox / sequencer-inbox / rollup contract addresses are per-chain L1 state, fetched once and reused. Ships in slice 5.
- **Timeboost.** Express Lane auctions, runtime-side `auctioneer_*` / `timeboost_*` namespaces, plus `arb_getRawBlockMetadata` for per-tx auction metadata. Ships in slice 5.

## Surface (current — slice 1)

| Export | Shape | Purpose |
|---|---|---|
| `estimate_arbitrum_fees` | `Readable<ArbitrumFees>` | L1 + L2 gas split via `NodeInterface.gasEstimateComponents`, in one shot. |

`ArbitrumFees`, `EstimateArbitrumFeesParameters` are exported from the root and from `@ethernauta/arbitrum/gas`. Subpath imports work as `@ethernauta/arbitrum/gas` for tree-shake-friendly consumption.

Bridge methods (Inbox / Outbox / Gateway, retryable-ticket lifecycle wrappers, L2→L1 withdrawal proofs, BoLD challenge contracts) are out of scope here and land in the bridge phase, after `Bridgable<T>` is designed.

## End-to-end — estimate gas on Arbitrum One

```ts
import { create_reader, encode_chain_id, http } from "@ethernauta/transport"
import { estimate_arbitrum_fees } from "@ethernauta/arbitrum"
import { eip155_42161 } from "@ethernauta/chain/eip155-42161"
import { AddressSchema, BytesSchema } from "@ethernauta/core"
import { parse } from "valibot"

const CHAIN_ID = encode_chain_id({
  namespace: "eip155",
  reference: eip155_42161.chainId,
})
const reader = create_reader([
  {
    chainId: CHAIN_ID,
    transports: [http("https://arb1.arbitrum.io/rpc")],
  },
])

const recipient = parse(
  AddressSchema,
  "0x70997970C51812dc3A010C7d01b50e0d17dc79C8",
)

const fees = await estimate_arbitrum_fees({
  tx: { to: recipient, input: parse(BytesSchema, "0x") },
})(reader({ chain_id: CHAIN_ID }))

// fees: {
//   gas_estimate, l1_base_fee_estimate, l2_base_fee
// }
```

One read against the `NodeInterface` virtual precompile at `0x00…C8`. The Nitro node intercepts and decodes the four-tuple into the L2-execution + L1-batch-posting split in one shot — simpler than the OP-Stack path, which needs three parallel `eth_*` calls before the `getL1Fee` read.

## Maxim alignment

This package exists exactly because of the [primitives-first maxim](/concepts/primitives-first):

- **[M1 — Primitives are first-class.](/concepts/primitives-first)** Every binding is a `Readable<T>` — precompile reads, RPC methods, fee composition. No coordinated wallet release needed to add a new precompile method; the folder-shaped operation is enough.
- **[M3 — Two consumer paths.](/concepts/two-paths)** Dapps can compose `estimate_arbitrum_fees` + `eth_signTransaction` + `eth_sendRawTransaction` end-to-end with no wallet (path 2), or hand a typed-tx envelope to the wallet (path 1). Both work on every Nitro chain.
- **[M4 — No paid services.](/concepts/primitives-first)** Every input is a public RPC, a vendored interface from `OffchainLabs/nitro-precompile-interfaces`, or a deployment address read directly from a Rollup contract on L1.
- **Hard rule 11.** Arbitrum precompiles aren't EIPs/ERCs — they live in `packages/arbitrum/`, not `packages/erc/`. Timeboost is also Arbitrum-specific, not a numbered standard.

## What this package does not do

- **Bridge methods.** Deposits, withdrawals, withdrawal-proof construction, retryable-ticket lifecycle wrappers. Lands with the bridge phase. The data path runs through [`Inbox`](https://docs.arbitrum.io/how-arbitrum-works/inside-arbitrum-nitro/#the-sequencerinbox-contract) / [`Outbox`](https://docs.arbitrum.io/how-arbitrum-works/inside-arbitrum-nitro/#the-outbox-contract) on L1 and the L2 gateway contracts.
- **BoLD challenge interaction.** Reading edges, posting commitments, etc. Out of scope until a clear consumer need surfaces. The BoLD contract set (`EdgeChallengeManager`, `AnchorStateRegistry`) is read from the Rollup contract at runtime if/when needed.
- **`arbtrace_*` namespace.** Pre-Nitro l2geth historical traces only; non-public; not exposed by mainstream RPC providers.
- **`arb_maintenanceStatus`, `arb_checkPublisherHealth`.** Operator-side diagnostics, not dapp surface — ship if/when an audience materializes.
- **Off-chain indexer wrappers.** Per [M4](/concepts/primitives-first) — no hosted-service dependencies.
