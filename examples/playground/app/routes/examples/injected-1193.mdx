# EIP-1193 + EIP-6963 — injected wallets

Four primitives close the loop on browser integration:

- **EIP-6963 announce/request events** — wallets dispatch
  `eip6963:announceProvider` on load; dapps dispatch
  `eip6963:requestProvider` to nudge late announcers. Each
  announce carries `{ info: { name, rdns, uuid, icon },
  provider }`.
- **`create_provider(provider)`** — adapts any EIP-1193
  provider (an announced wallet, `window.ethereum`, a test
  mock) into a single factory with `.signer({ chain_id })`
  feeding `Signable<T>` methods and `.reader({ chain_id })`
  feeding `Readable<T>` methods. Same call shape as
  `create_reader(CHAINS)` / `create_signer(CHAINS)` — only
  the transport-construction line differs.
- **`remember_picked_provider` / `restore_picked_provider`** —
  persist the user's chosen rdns and rehydrate the live
  Provider on the next page load via a fresh 6963 announce
  handshake. The Provider object itself is never serialized;
  only the rdns is.
- **`watch_accounts` / `watch_chain`** — typed wrappers over
  `provider.on("accountsChanged" | "chainChanged", …)` that
  validate the payload before invoking the handler.

## The code

```ts
import { eth_getBalance } from "@ethernauta/eth"
import { eth_requestAccounts } from "@ethernauta/eip/1102"
import {
  create_provider,
  type Provider,
  watch_accounts,
  watch_chain,
} from "@ethernauta/eip/1193"
import {
  ANNOUNCE_EVENT,
  type EIP6963AnnounceProviderEvent,
  type EIP6963ProviderDetail,
  remember_picked_provider,
  REQUEST_EVENT,
  restore_picked_provider,
  type Storage,
} from "@ethernauta/eip/6963"
import { encode_chain_id } from "@ethernauta/transport"

const PICKED_KEY = "ethernauta:picked-wallet"

const local_storage: Storage = {
  get: (key) => window.localStorage.getItem(key),
  set: (key, value) => window.localStorage.setItem(key, value),
  remove: (key) => window.localStorage.removeItem(key),
}

// 1. Listen for announces, then trigger requestProvider so
//    wallets that announce on-demand surface as well.
const providers: EIP6963ProviderDetail[] = []
function on_announce(event: Event) {
  const detail =
    (event as EIP6963AnnounceProviderEvent).detail
  if (providers.some((p) => p.info.rdns === detail.info.rdns)) {
    return
  }
  providers.push(detail)
}
window.addEventListener(ANNOUNCE_EVENT, on_announce)
window.dispatchEvent(new Event(REQUEST_EVENT))

// 2. Pick a wallet — fresh user pick, or rehydrated from a
//    previously-persisted rdns.
const restored = await restore_picked_provider({
  storage: local_storage,
  key: PICKED_KEY,
  ms: 200,
})
const picked = restored ?? (providers[0]?.provider as Provider)

// On a fresh pick, persist the rdns so the next reload
// can call restore_picked_provider and end up here without
// the user re-choosing.
remember_picked_provider({
  storage: local_storage,
  key: PICKED_KEY,
  rdns: providers[0].info.rdns,
})

// 3. Wrap the provider once — both .signer and .reader come
//    from the same factory call.
const factory = create_provider(picked)

const current_hex = (await picked.request({
  method: "eth_chainId",
})) as string
const chain_id = encode_chain_id({
  namespace: "eip155",
  reference: Number.parseInt(current_hex, 16),
})

// Signable: ask the wallet for accounts.
const accounts = await eth_requestAccounts()(
  factory.signer({ chain_id }),
)

// Readable: route eth_getBalance through the wallet's
// selected RPC. Same call shape as a non-wallet reader —
// only the transport-construction line differs.
const balance = await eth_getBalance({ address: accounts[0] })(
  factory.reader({ chain_id }),
)

// 4. Reactively watch updates from the injected provider.
const stop_a = watch_accounts(picked, (next) => {
  // re-render with `next`
})
const stop_c = watch_chain(picked, (next) => {
  // re-render with `next` (hex chain id)
})
```

## The two paths, side by side

The same `eth_getBalance` call works against a public RPC
with no wallet — just swap the transport:

```ts
import { create_reader, http } from "@ethernauta/transport"

const reader = create_reader([
  {
    chainId: "eip155:1",
    transports: [http("https://ethereum-rpc.publicnode.com")],
  },
])
const balance = await eth_getBalance({ address })(
  reader({ chain_id: "eip155:1" }),
)
```

`create_provider(wallet).reader({ chain_id })` and
`create_reader(CHAINS)({ chain_id })` produce structurally
the same `ResolvedReader`. The method doesn't know which one
it's running against — that's the point.
